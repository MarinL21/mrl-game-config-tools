## 调试技巧

### Skill写入权限问题
<!-- 日期: 2026-01-13 -->

#### 场景
尝试向项目级 `.cursor/skills/` 目录写入文件时

#### 经验
**项目级 skill 目录可能有写入限制，用户级 skill 目录通常可以正常写入**

#### 详细说明
- 项目级路径 `项目/.cursor/skills/` → 写入可能被拒绝
- 用户级路径 `C:\Users\xxx\.cursor\skills\` → 写入正常
- 原因可能是：Cursor IDE 占用、特殊权限设置、路径中文字符

#### 解决方案
1. 优先使用用户级 skills 目录
2. 如需项目级，让用户手动创建或调整权限

## Git 操作

### Git 多仓库项目识别
<!-- 日期: 2026-01-15 -->

#### 场景
用户要求对比本地和远程 git 分支差异，但项目根目录包含多个独立的 git 子仓库。

#### 经验
**执行 Git 操作前，必须先识别项目结构是单仓库还是多仓库结构**

#### 详细说明
常见的多仓库结构特征：
1. **git submodules** - 根目录有 `.gitmodules` 文件
2. **多项目工作区** - 根目录下每个子目录都是独立的 git 仓库（各自有 `.git` 目录）
3. **monorepo** - 虽然是单仓库，但结构复杂需注意

#### 正确做法
```bash
# 1. 先检查根目录的 git 状态
git status
git remote -v

# 2. 如果发现没有远程或异常，检查子目录
ls -la  # 查看有哪些子目录

# 3. 检查是否有 submodules
cat .gitmodules 2>/dev/null

# 4. 检查各子目录是否是独立仓库
for dir in */; do
  if [ -d "$dir/.git" ]; then
    echo "$dir 是独立 git 仓库"
  fi
done
```

#### 反例
❌ 直接对根目录执行 `git fetch origin` 然后报错 "origin does not appear to be a git repository"
❌ 没有询问用户就假设根目录是唯一的仓库

#### 正确流程
1. 先用 `ls` 查看项目结构
2. 检查根目录的 `git remote -v`
3. 如果根目录不是主仓库，询问用户或检查各子目录
4. 对每个需要操作的子仓库分别执行 git 命令
