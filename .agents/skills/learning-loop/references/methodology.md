# 方法论模板

当零散经验积累到一定数量，可升级为结构化方法论。

## 方法论结构模板

```markdown
# [方法论名称]

## 概述
[一句话说明这个方法论解决什么问题]

## 适用场景
- [场景1]
- [场景2]
- [场景3]

## 核心原则
1. **[原则1名称]**：[简要说明]
2. **[原则2名称]**：[简要说明]
3. **[原则3名称]**：[简要说明]

## 执行步骤

### 步骤1：[步骤名称]
[具体做法]

**检查点**：[如何判断这步完成]

### 步骤2：[步骤名称]
[具体做法]

**检查点**：[如何判断这步完成]

### 步骤3：[步骤名称]
[具体做法]

**检查点**：[如何判断这步完成]

## 常见陷阱
- ❌ [陷阱1]：[为什么是陷阱，如何避免]
- ❌ [陷阱2]：[为什么是陷阱，如何避免]

## 示例

### 好的例子
[具体示例]

### 反面例子
[错误示例及分析]

## 经验来源
- [来源1：简要说明]
- [来源2：简要说明]
```

## 方法论升级流程

### 1. 触发条件
- 同一领域经验 ≥ 5 条
- 经验之间有明显关联
- 可以抽象出通用模式

### 2. 升级步骤

```
1. 收集相关经验
   ↓
2. 识别共同模式
   ↓
3. 抽象核心原则
   ↓
4. 设计执行步骤
   ↓
5. 补充示例和陷阱
   ↓
6. 用户确认
   ↓
7. 写入对应 skill
```

### 3. 写入位置
- 如果与现有 skill 强相关 → 写入该 skill 的 SKILL.md 或 references/
- 如果是新领域 → 创建新 skill
- 如果是通用方法论 → 保留在 learning-loop/references/

### 4. 升级后处理
- 在 _index.md 中记录方法论
- 原始经验可保留用于追溯
- 通知用户已升级为方法论

## 方法论质量检查

升级为方法论前，检查：

- [ ] 是否有明确的适用场景？
- [ ] 原则是否可操作？
- [ ] 步骤是否完整？
- [ ] 是否有具体示例？
- [ ] 是否标注了常见陷阱？
- [ ] 经验来源是否清晰？
