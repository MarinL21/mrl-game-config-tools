# 自循环学习系统 (Learning Loop)

让 AI 越用越聪明的经验积累系统。

## 核心工作流

### 1. 识别学习触发信号

当出现以下任何信号时，**立即激活学习模式**：

---

#### A. 实时对话中的学习

**直接修正型**
- "你错了"、"不对"、"应该是..."
- "这样不行"、"换个方式"
- "我说的是..."、"你理解错了"

**偏好表达型**
- "我喜欢..."、"我习惯..."
- "下次这样做"、"以后注意"
- "我们团队的规范是..."

**经验分享型**
- "记住"、"注意"、"技巧是..."
- "最佳实践"、"诀窍"、"秘诀"
- "这是我的经验"

---

#### B. 反思批评中的学习 ⭐

**批评反馈型**
- "这次做得不好"、"不够好"
- "还需要改进"、"差点意思"
- "质量不行"、"不专业"

**反思总结型**
- "反思一下"、"复盘"
- "这次的教训是"、"下次要避免"
- "问题出在..."、"根本原因是..."

**失败分析型**
- "这个方案失败了"、"没有达到预期"
- "用户不买账"、"数据很差"
- "被打回了"、"领导不满意"

---

#### C. 历史内容中的学习

**聊天记录**
- 用户分享与其他人/AI 的对话
- 历史项目的讨论记录

**文档内容**
- 复盘文档、会议纪要
- 邮件内容、工作日志
- 项目总结、经验报告

---

#### D. 外部知识中的学习

**行业知识**
- 用户分享的文章、教程
- 行业最佳实践、规范文档
- 竞品分析、市场调研

**团队规范**
- 公司内部规范
- 团队约定、流程文档
- 代码规范、设计规范

---

#### E. 隐性信号中的学习 ⭐

**行为信号**（需要主动识别）
- 用户修改了你的输出（查看 diff）
- 用户放弃了你的建议，自己重写
- 用户多次追问同一问题（说明没讲清楚）
- 用户说"算了"、"不用了"

**情绪信号**
- 用户表达不满、失望
- 用户表达惊喜、认可（正向经验）

---

#### F. 总结请求型

- "总结一下刚才的经验"
- "把这个记下来"、"写进 skill"
- "形成方法论"、"沉淀下来"

### 2. 经验提取流程

识别到学习信号后，根据不同类型执行不同的提取流程：

#### 2.1 修正/批评类 → 提取教训

```
[提取教训]
1. 问题：我做错了什么？
2. 原因：为什么会犯这个错？
3. 正解：正确的做法是什么？
4. 预防：如何避免再犯？
5. 适用：这个教训适用于哪些场景？
```

#### 2.2 经验分享类 → 提取方法

```
[提取方法]
1. 场景：什么情况下使用？
2. 方法：具体怎么做？
3. 要点：关键注意事项？
4. 示例：有没有具体例子？
5. 边界：什么情况下不适用？
```

#### 2.3 失败分析类 → 提取复盘

```
[提取复盘]
1. 背景：当时的目标和约束？
2. 过程：做了什么决策？
3. 结果：为什么失败？
4. 根因：深层原因是什么？
5. 改进：下次如何做得更好？
```

#### 2.4 隐性信号类 → 主动反思

```
[主动反思]
1. 信号：用户的行为说明什么？
2. 差距：我的输出和预期差在哪？
3. 改进：如何调整？
4. 确认：向用户确认理解是否正确
```

#### 2.5 外部知识类 → 提取精华

```
[提取精华]
1. 来源：信息出处？
2. 核心：关键观点/方法是什么？
3. 转化：如何应用到我们的场景？
4. 关联：与现有哪些 skill 相关？
```

### 3. 经验归类与存储

#### 3.1 核心原则：经验分发到角色 Skill

**经验不集中存储，而是分发到对应的角色 Skill 中**，让每个 Skill 自己越来越完善。

#### 3.2 Skill 映射表

| 领域 | 对应 Skill | 存储位置 | 示例经验 |
|------|-----------|----------|----------|
| 品牌设计 | `brand-guidelines` | 用户级 | Anthropic 配色、字体规范 |
| Word 文档 | `docx` | 用户级 | 文档创建、编辑、修订追踪 |
| PDF 处理 | `pdf` | 用户级 | 提取、合并、表单填写 |
| PPT 演示 | `pptx` | 用户级 | 创建、编辑、模板使用 |
| MCP 开发 | `mcp-builder` | 用户级 | 服务器构建、工具设计 |
| Skill 创建 | `skill-creator` | 用户级 | Skill 结构、最佳实践 |
| Cursor 规则 | `creating-cursor-rules` | 用户级 | RULE.md 格式、规则类型 |
| Cursor Skills | `creating-skills` | 用户级 | SKILL.md 格式、触发描述 |
| 子代理 | `creating-subagents` | 用户级 | subagent 创建、system prompt |
| Cursor 设置 | `update-cursor-settings` | 用户级 | settings.json 修改 |
| Cursor 使用 | `learning-loop` | 用户级 | Skill 位置、Rules 规范 |
| 通用偏好 | `learning-loop` | 用户级 | 沟通风格、输出格式 |

#### 3.3 存储位置决策树

```
收到经验/聊天记录 →
│
├── 1. 识别经验属于哪个领域
│
├── 2. 找到对应的 Skill
│   ├── 用户级 Skill → ~/.cursor/skills/[skill-name]/
│   └── 项目级 Skill → [项目目录]/.cursor/skills/[skill-name]/
│
├── 3. 判断写入位置
│   ├── 重要/通用经验 → 直接更新 SKILL.md（追加到相应章节）
│   └── 细节/补充经验 → 写入 knowledge-base/[分类].md
│
├── 4. 如果该 Skill 没有 knowledge-base 目录
│   └── 自动创建：[skill目录]/knowledge-base/_index.md
│
└── 5. 如果找不到对应 Skill
    └── 提示用户："建议创建新 skill: [建议名称]，是否创建？"
```

#### 3.4 聊天记录学习模式

当用户分享**历史聊天记录**时，执行以下流程：

```
1. 扫描聊天记录，识别所有"优化需求"和"经验分享"
2. 按领域分类，生成经验清单
3. 逐条确认：
   - "发现 N 条 [领域] 经验，是否写入 [skill-name]？"
4. 批量写入对应 Skill
5. 输出写入报告
```

### 4. 写入经验

将经验写入 `knowledge-base/` 目录，使用标准格式：

```markdown
## [经验标题] 
<!-- 日期: YYYY-MM-DD -->

### 场景
[触发这个经验的具体场景]

### 经验
[核心要点，用一句话概括]

### 详细说明
[具体做法和注意事项]

### 反例
[错误示范，可选]

### 来源
[用户反馈 / 项目实践 / 调试发现]
```

### 5. 主动确认

写入后，向用户确认：

```
✅ 已记录经验：[经验标题]
📂 存储位置：[skill名/knowledge-base/分类.md]
🏷️ 分类：[领域标签]

是否需要调整？
```

## 经验库结构

### 分布式存储架构

经验**分散存储在各个 Skill 中**，每个 Skill 都可以有自己的 `knowledge-base/` 目录：

```
用户级 Skills (~/.cursor/skills/)
├── docx/
│   ├── SKILL.md
│   └── knowledge-base/        # Word 文档处理经验
│       ├── _index.md
│       └── templates.md       # 模板使用经验
│
├── pdf/
│   ├── SKILL.md
│   └── knowledge-base/        # PDF 处理经验
│
├── pptx/
│   ├── SKILL.md
│   └── knowledge-base/        # PPT 处理经验
│
├── learning-loop/
│   ├── SKILL.md
│   └── knowledge-base/        # 通用经验（Cursor 使用、沟通偏好）
│       ├── _index.md
│       ├── preferences.md     # 用户通用偏好
│       ├── cursor-usage.md    # Cursor 使用技巧
│       └── workflow.md        # 工作流程经验
│
项目级 Skills ([项目目录]/.cursor/skills/)
├── project-specific-skill/
│   ├── SKILL.md
│   └── knowledge-base/        # 项目特定经验
│       └── conventions.md     # 项目约定经验
```

### 本 Skill 的经验库

`learning-loop/knowledge-base/` 只存储**通用经验**：
- `preferences.md` - 用户沟通偏好、输出格式偏好
- `cursor-usage.md` - Cursor/Skill/Rule 使用技巧
- `workflow.md` - 跨领域工作流程
- `coding.md` - 通用编程经验

## 定期回顾

每当开始新对话时，如果涉及相关领域，**主动读取对应经验文件**，确保学到的经验被应用。

读取顺序：
1. `knowledge-base/_index.md` - 了解有哪些经验
2. 与当前任务相关的具体经验文件

## 经验升级

当同一领域的经验积累到 5 条以上时：
1. 提示用户："[领域] 已积累 N 条经验，是否整合成方法论？"
2. 若同意，将零散经验归纳为结构化的方法论
3. 写入对应 skill 的主 SKILL.md 或 references/

## 重要原则

### 核心心态
1. **永远保持学习敏感度**：任何对话都可能包含学习机会
2. **批评是最好的老师**：用户的不满和批评是最宝贵的学习来源
3. **失败比成功更值得记录**：失败案例的教训往往更有价值

### 操作规范
4. **主动识别**：不等用户说"记住"，发现任何学习信号就主动提取
5. **确认写入**：写入前简要说明，写入后确认成功
6. **避免重复**：写入前检查是否已有类似经验，有则更新而非新增
7. **持续应用**：新对话开始时，回顾相关经验
8. **定期归纳**：零散经验积累后，升级为方法论

### 学习范围（全面覆盖）
9. **不只是聊天记录**：反思、批评、复盘、失败案例、外部文章都要学习
10. **注意隐性信号**：用户修改输出、放弃建议、多次追问都说明有问题
11. **正向经验也要记**：用户认可的做法同样值得沉淀
