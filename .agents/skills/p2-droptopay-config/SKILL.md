# P2 掉落转付费配置 Skill

## Scope（这个 skill 只做「换档」不做「新建」）

**做**：把一组已经配好的"掉落转付费"实例（如复活节版）的节日专属位换成新节日（如拓荒节版）。

**不做**（碰到要切别的 skill 或问用户）：
- 全新增加一套"掉落转付费第N套"模板（数值层重设 base_activity / ui_template / drop 池新建）
- 21218379 之外的 drop_topay_show 实例新建
- 2124 drop 池数值改造（11119334 系玩法积分道具的权重 / wgt 调整）
- 2121 new_progress 90+ 行阶段奖励的内容改动（这是数值层，归 p2-numerical-design）
- 2137 retake 补领配置
- 2011/2013 IAP 累充配置（归 iap-leichong-sync）
- 1011 翻译文案（归 p2-translation-automatic）

## 工作流（4 步）

### Step 0 — 自主学习（必做，不信文档快照）

每次都从真实表读 ≥2 节日对照：
1. 读 2112.B 列搜"掉落转付费"，列出历史所有套
2. 让用户确认这次换档基于哪一套（默认第二套）
3. 读出本套全部行的当前节日命名（comment / show_hud / 子活动 IDs）
4. 输出现状给用户确认后再 plan

### Step 1 — 收齐用户输入（**触发即问，不替用户决定**）

| 项 | 必填 | 备注 |
|---|---|---|
| 1. 套数 | 必 | 默认第二套 21127558/21127527/21127528 |
| 2. 新节日中文名 | 必 | 拓荒节 / 复活节 / ... |
| 3. 新表情包 item.id | 必 | 1111 表 grep 选下一个未占用的 |
| 4. 新 BP 道具 item.id | 必 | 查上表节日映射 |
| 5. 新 show_hud | 必 | 每节日独立，UI 同学预分配 |
| 6. 商店招牌位 (21162376) | 必 | 用户每次单独指定 |
| 7. 是否同步改 2111 calendar | 必 | 默认只改主行 21127558 那一条 |
| 8. 是否清理 LC_KEY / constant 历史错位 | 选 | 默认 N |

### Step 2 — Plan dry-run

按"必改清单"列出每个 cell 的 before/after，**不动表**。让用户看一遍再 apply。

### Step 3 — Apply

`gws sheets spreadsheets values batchUpdate` 按表分批：
- 2112: 6 cell（3 行 × B + R）
- 2121: 1 cell（D）
- 2116: 2 cell（21162375.E + 21162381.E + 招牌位 21162376.E 视情况）
- 2111: 1 cell（C，主行）

总计典型 9-10 cell。

### Step 4 — Verify 回读

用 `batchGet` 把刚写的全部 range 拉出，逐字段 assert：
- 2112 三行 comment 含新节日名、show_hud 等于新值
- 2121 21218379 reward 数组第 1 位 item.id == 新表情
- 2116 第 1 档 item_get item.id == 新表情；第 7 档 == 新 BP 道具
- 2111 主行 comment 含新节日名

## ⚠️ 容易踩的坑

### 1. 21162376「招牌位」每次问用户
当前脚本看到的值（如周年弹珠抽奖道具 11112649）**不是默认模板**，是用户那次手动塞的。**绝不替用户拍**。

### 2. 第 7 档 BP 道具是隐蔽节日专属位
21162381 当前 item.id 名字直接写"魔术棒-复活节通用活动BP道具"，看着像通用其实是上节日残留。换档不换=玩家在新节日拿到上节日的 BP 道具，废卡。

### 3. drop 池 (2124) 不要碰
21241997-21242003 七行的奖励池全是玩法层共用，看到 comment 写"2025拓荒节"也是历史命名，业务上没影响。**误改会破坏数值平衡**。

### 4. 2111 calendar 不止一条
同一个 activity_id 可能有 normal + ark 两套排期 + 多个节日历史复用。**默认只改本次主行那一条**，其它由用户决定。

### 5. 2112 主行的 constant / LC_KEY 历史错位是常态
如 21127527 当前 `constant=event_labor_2025_2_drop` 但 comment 之前写"复活节"——这是上次换档时 comment 漏改、constant 没人改的存量。**默认不清理**（清理需用户授权 + 同步翻译表）。

### 6. show_hud 不要瞎给
新节日 show_hud（如拓荒=21680032）必须是 UI 同学/21680 表里**真实存在**的 ID。脚本不验证，只搬运。错了 UI 跳转会断。
