# P2 节日活动三类礼包配置 Skill

## 1. 三类礼包业务定位

| 类别 | 售卖 | 价位 | 卖点 | 2112 组件 | 涉及表 |
|---|---|---|---|---|---|
| 行军表情礼包 | 单独 | $4.99 | 动态表情 | `discount` + `emoji_show` | 2112/2121×2/2011/2013/1111/1180/1168/1511/2111 |
| 行军特效礼包 | 单独 | $19.99 | 行军特效永久版(低级) | `package` | 2112/2135/2011/2013/1111×12/1365×2/1511×2/1512×2/2111 |
| 联动礼包 | **否(条件奖励)** | 无 | 买完前两包后额外 bonus | `unite_pkg` | 2112/2121 |

**联动礼包不是第三个直购包**，是"同时买了表情包+特效包后"的条件奖励。触发条件在 `2121.A_MAP_expr.args[]`，每个 arg 的 `id` 指向一个要购买过的 2013 IAP 模板。

## 5. 操作规则

### 5.1 patch-from-ref 原则

写新行的**唯一正确方式**：读同类型真实参考行（同一种礼包、≥2 个节日），仅 PATCH 必换字段。未 patch 字段原样继承参考行（自动符合空值约定 `""`/`NULL`/`{}`/`[]`、JSON 紧凑格式、通用字段不误改）。

### 5.2 字段类型默认值约定

| 前缀 | 空值写法 | 错误写法 |
|---|---|---|
| `A_INT_*`/`S_INT_*`/`C_INT_*`/`A_FLT_*` | `0` | 留空 |
| `A_STR_*`/`S_STR_*`/`C_STR_*`/`N_STR_*` | 字面量 `""` | 真空 cell |
| `A_MAP_*`/`S_MAP_*`/`C_MAP_*` | `{}` | 留空 |
| `A_ARR_*`/`S_ARR_*`/`C_ARR_*` | `[]` | 留空 |
| 特殊 | `NULL` 字面量 | — |

JSON 紧凑格式：`json.dumps(obj, separators=(",",":"), ensure_ascii=False)`

### 5.3 资源链路闭环

每个被引用的 id 都必须在对应表存在。配完跑 `scripts/check_refs.py`，缺失为 0 才通过。
- 2013/2121 → 1111（`typ=item` 才查，`typ=xp` 跳过）
- 1111(marching_effect) → 1365 → 1512、1511、**1168**
- 1111(map_emoji) → 1180 → 1168、1511
- 1168 行军特效：`C_STR_item_label=<1365套id>`，`access_group.args=<跳转活动2112id>`
- 1168 行军表情：`C_STR_item_label=non_item`，`access_group.args=<2112活动id>`
- **嵌入 id 易漏**：`1111.A_ARR_use_labels` 里的 1365 套 id 是字符串形式

### 5.4 写入位置规则

**所有表通用铁律**：新行落点 = 数值前驱所在行 + 1（前驱 = 小于 new_id 的最大 ID）。**禁止 `values.append` 到表格底部**，即使前驱正好在底部也要走 `insertDimension` 流程。详见 `p2-unite-gift-pack` SKILL.md §ID 顺序规则。

**特殊表的补充约束**（都是前驱规则的同义表述）：
- **2112**：节日活动新行的数值前驱是上一条节日活动行（`21129xxx`），insert 进去后会自然落在 `21128001 节日占位符` 上方。改 2112 后必须同步：`2011.time_info.actv_id`、`2112.filter.iap_purchases.id`、`1168.access_group.args`。
- **2111**：三类礼包**都要**上 2111（包括联动，虽然 2112.calendar=0）。新行前驱按 `21115767` 后顺延的最大节日 ID 找，insert 后自然落在 `21116001 节日占位符` 上方。
- **1180**：新表情行按前驱规则，当前前驱是 `11800029`（新行 `11800030` 就落在 `11800029` 的下一行）。
- **2011**：节日礼包 iap_config 新实例**默认从 `2011610000` 起分配**（向后递增）。历史 `20115xxxxxx` / `20114xxxxxx` 段已被 bp/其他活动占用，曾在 2026 拓荒节导致 ID 重复（`2011510010/11` 与 `武装通行证bp-schema3-5/6` 冲突）。分配前必须读 2011 主表确认 `2011610xxx` 段尚未占用，跳过已用号。修改 2011 id 后必须同步：`2135.A_INT_iap`、`2013.A_INT_config_id`、`2121.A_ARR_status[].id`（typ=iap 时）。

ID 不可重复，顺延分配。

### 5.5 测试页签规则

- 只有用户明确要求才建测试页签
- 命名：`<原页签前缀>_TEST_<节日pinyin><年>`
- 位置：紧贴 QA 主页签右侧（index=main+1）
- 内容：**一律按正式配置写**，不加 `_test` / `(测试)` 标识

## 6. 换档 SOP（标准作业顺序）

### Step 0: 自主学习（每次换档必做，不可跳过）

在动手配置之前，先用 gws 从真实 QA 主页签**读取 ≥2 个不同节日的同类型完整配置**，逐字段输出对照表。这一步的目的是让自己（而不是文档）亲眼看到"哪些字段跨节日一样（通用）、哪些不一样（节日专属）"。

```
必读清单（以行军特效礼包为例）：
  1. 读科技节特效礼包 2013 行（完整 other_items JSON）
  2. 读情人节特效礼包 2013 行（完整 other_items JSON）
  3. 逐位对比：[0]~[5] 每个 item_id 是否相同
  4. 相同 → 标记"通用不换"；不同 → 标记"节日专属要换"
  5. 把对比结果输出给用户确认后，再开始写配置

  对联动礼包 2121 reward 同理做一遍。
  对行军表情礼包 2013 other_items 同理做一遍。
```

**对资源链也做同样的学习**：
```
  6. 读科技节 1111 行军特效 item（任一时长版本），完整 25 个字段
  7. 读情人节对应行
  8. 逐字段对比，列出"要改 / 不要改"两个清单
  9. 特别检查嵌入 id 字段：A_ARR_use_labels / A_MAP_category_param
  10. 读 1365 / 1168 / 1512 / 1511 同理
```

**为什么不能跳过**：skill 文档里的通用/专属清单（§4）是基于 2026 科技节+情人节验证的快照。但游戏版本会迭代，未来某次换档时道具构成可能变化。每次亲自读真实数据对照，才能发现文档快照和实际的偏差。

### Step 1~8: 执行

1. **确认参数**：向用户确认——本季节日自选箱 id / 主外显特效 item_id / Banner 美术路径 / 1512 `C_STR_file` 美术路径 / 1168 高级跳转活动 id。不确定就问
2. **分配 ID**：2112 从 21129000 顺延；2111 从 21115767 顺延；1111/1365/1511/1512/1168 从各表最后一行 +1 顺延
3. **建资源链**：1512→1511→1365→1168→1111（先底层后上层）
4. **建主链路**：2112→2135→2011→2013→2121→2111（patch-from-ref，通用道具从 Step 0 的对照结果确认不换）
5. **逐字段 diff 校验**：对每张表，把新写的行和参考行逐字段对比，列出所有差异。**只有 Step 0 标记为"要改"的字段才应该出现在差异列表里**。如果有预期外的差异 → 停下来修正，不要继续
6. **资源链校验**（`scripts/check_refs.py`）：缺失为 0 才通过
7. **迁移 QA**：2112 插到 21128001 上方；2111 插到 21116001 上方；其他追加末尾
8. **回读确认**：读 QA 页签最终落点，再验一次
