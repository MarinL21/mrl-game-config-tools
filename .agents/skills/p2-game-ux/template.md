# P2 / AOA 活动 UX 方案模板

本模板用于快速产出 `P2 / AOA` 的活动交互方案文档。

适用范围：

- 节日活动
- 累充返利
- 抽奖玩法
- 集卡收集
- 小队合作活动
- 运营付费活动

## 模板 1：标准活动页

```markdown
# [活动名称]

## 1. 背景与目标
- 功能背景：[一句话说明活动存在原因]
- 用户目标：[玩家来这里主要做什么]
- 商业目标：[拉活跃 / 拉付费 / 拉回流 / 拉协作]
- 体验目标：[要让玩家感受到什么]

## 2. 入口设计
- 主入口：[主城 HUD / Banner / 节日页签 / 弹脸弹窗]
- 次入口：[任务跳转 / 邮件 / 限时提示]
- 关闭后回流：[关闭后玩家回到哪里]

## 3. 页面分层
- L1 入口层：[只负责露出与引导]
- L2 主玩法页：[核心操作、奖励、任务、规则摘要]
- L3 弹窗层：[确认、结果、规则、奖励预览]

## 4. 页面结构
- 左侧：页签 / 模式切换
- 中央：核心玩法区
- 右侧：任务 / 奖励 / 规则摘要 / 商店
- 顶部：标题 / 倒计时 / 货币 / 帮助
- 底部：主按钮 / 进度 / 阶段奖励

## 5. 核心交互流程
进入活动 -> 理解当前目标 -> 执行一次核心行为 -> 获得结果反馈 -> 查看累计收益 -> 决定继续或退出

## 6. 关键状态设计
- 初始态：[首次进入看到什么]
- 进行态：[正常游玩中看到什么]
- 可领奖态：[哪些元素高亮]
- 完成态：[活动阶段完成后怎么展示]
- 异常态：[资源不足 / 次数不足 / 背包满 / 活动结束]

## 7. 组件规范
- 主按钮：[文案、颜色、位置]
- 次按钮：[文案、位置、使用场景]
- 奖励格：[品质、数量、已领取态]
- 进度条：[达成条件、领奖节点]
- 倒计时：[固定位置]
- 红点：[仅用于有收益可拿]

## 8. 商业化挂点
- 挂点 1：[什么时机出现]
- 挂点 2：[与玩家动机的关系]
- 原则：[不打断主理解链路]

## 9. 动效与反馈
- 点击反馈：[按钮缩放 / 卡片高亮]
- 成功反馈：[奖励飞入 / 数字滚动]
- 大奖反馈：[强演出 / 聚焦 / 破框]
- 失败反馈：[明确原因 + 获取入口]

## 10. 风险点
- 理解成本风险：
- 信息拥挤风险：
- 商业化打断风险：
- 状态不清风险：

## 11. 验收清单
- [ ] 玩家 3 秒内能看懂主目标
- [ ] 玩家 1 次点击后能得到清晰反馈
- [ ] 玩家知道下一步去哪里
- [ ] 免费路径和付费路径都成立
```

## 模板 2：组队合作活动

```markdown
# [活动名称]

## 1. 目标
- 玩法目标：[协作完成什么]
- 社交目标：[邀请 / 组队 / 联盟活跃]
- 商业目标：[礼包 / 加速 / 次数 / 充值]

## 2. 页面结构
- 主页面：活动主物体 / 阶段进度 / 主操作
- 队伍面板：队员、贡献、状态、邀请
- 奖励页：个人奖励、团队奖励、阶段奖励
- 子弹窗：邀请、确认退出、领奖结果

## 3. 核心流程
进入活动 -> 创建/加入队伍 -> 查看当前阶段 -> 执行个人行为 -> 推动团队进度 -> 阶段领奖 -> 下一阶段

## 4. 状态矩阵
- 未组队：引导创建或加入
- 已组队未开始：展示队员和准备态
- 推进中：展示个人贡献 + 团队进度
- 可领奖：高亮阶段节点和领取入口
- 已完成：展示结算与回流入口

## 5. 信息分区
- 我的任务：[我现在能做什么]
- 队伍进度：[团队目前到哪了]
- 队员状态：[谁在线、谁可协助]
- 奖励目标：[做完能拿什么]

## 6. 风险控制
- 防止玩家不知道自己该干什么
- 防止只看到团队数据，看不到个人收益
- 防止邀请链路太深
- 防止退出/补位缺少反馈
```

## 模板 3：付费活动 / 礼包活动

```markdown
# [活动名称]

## 1. 目标
- 核心卖点：[折扣 / 成长 / 返利 / 保底 / 累积]
- 玩家动机：[为什么会想买]

## 2. 页面结构
- 主装置 / 主商品：[价值感中心]
- 当前价格区：[现价、原价、最低价]
- 行为进度区：[还能降多少 / 还能解锁多少]
- 奖励预览区：[买了拿什么]
- 规则区：[如何继续推进]

## 3. 核心流程
进入活动 -> 理解价值 -> 执行前置行为 -> 价格/奖励变化 -> 确认购买 -> 领取结果

## 4. 必须同屏的信息
- 当前价
- 原价
- 本次收益
- 下一步收益
- 触发条件

## 5. 风险点
- 价格逻辑不透明
- 玩家看不出便宜在哪里
- 付费入口太早打断
```

## 推荐输出顺序

做 `P2/AOA` 活动方案时，优先按这个顺序写：

1. 先写目标。
2. 再写入口和页面结构。
3. 再写完整流程。
4. 再写状态与反馈。
5. 最后写商业化和风险点。

## 快速套用示例

### 套用到 Bingo 活动

- 模板：`标准活动页`
- 主玩法区：Bingo 棋盘
- 右侧：次数、返利任务、大奖预览
- 主按钮：抽取 / 点亮

### 套用到 组队维修活动

- 模板：`组队合作活动`
- 主玩法区：赛车维修主物体
- 右侧：队员列表、贡献值、阶段目标
- 商业化：加速、材料包、阶段礼包

### 套用到 砍价礼包

- 模板：`付费活动 / 礼包活动`
- 主玩法区：矿机或矿石演出
- 同屏信息：当前价、原价、最低价、剩余可降次数
