# P2 / AOA UX 参考案例库

本文件整理当前已提供的 `P2 / AOA` 参考 UX 图，供产出交互方案时快速复用。

使用方式：

- 先判断新需求更像哪一类案例。
- 优先复用现成的页面骨架、状态流转和交互节奏。
- 如果需求同时命中多个案例，按“主玩法案例 + 商业化案例 + 反馈案例”组合。

## 案例 1：红色英雄系统

### 功能定位

- 英雄成长扩展
- 战力提升展示
- 能力共享 / 共鸣 / 天赋强化

### 页面骨架

- 左侧：英雄列表、切换入口、子系统入口
- 中央：当前英雄主体展示
- 右侧：属性、能力槽、升级按钮、资源消耗
- 弹窗：共享、替换、确认、结果说明

### 核心流程

`主界面 -> 打开能力共享 -> 选择材料/英雄 -> 确认共享 -> 展示强化结果 -> 返回英雄页回显`

### 可复用规则

- 英雄成长必须把“当前值、增量、目标值”同时展示。
- 共享系统必须写清楚共享关系与替换后影响。
- 天赋树或节点成长要有路径感，不要只堆一屏节点。

### 风险点

- 成长入口过多导致认知负担大。
- 共享关系不透明，玩家不敢点。

## 案例 2：砸金蛋活动

### 功能定位

- 节日充值活动
- 条件达成后解锁开启动作
- 开蛋与奖励揭晓组合反馈

### 页面骨架

- 左侧：活动页签
- 中央：金蛋主体、阶段状态、开启入口
- 右侧：任务、充值进度、奖励说明
- 弹窗：确认开启、奖励结果、引导说明

### 核心流程

`进入活动 -> 完成充值/任务 -> 解锁金蛋 -> 点击开启 -> 播放开蛋动画 -> 奖励展示`

### 可复用规则

- 主装置必须是玩法视觉中心。
- “未开启”“可开启”“已开启”三态必须差异明显。
- 奖励结果页要能承接“继续开”“查看累计”“退出”。

### 风险点

- 开启动画太弱，玩家感知不到仪式感。
- 不知道为什么现在不能开。

## 案例 3：猴猴币活动

### 功能定位

- 储蓄罐 / 投币成长活动
- 累积投入换阶段收益
- 中间载具或形象承担成长演出

### 页面骨架

- 左侧：页签
- 中央：猴子储蓄主体、成长变化
- 右侧：货币、收益、阶段奖励、规则
- 弹窗：投入确认、奖励结果、阶段完成

### 核心流程

`进入活动 -> 投入指定资源 -> 装置成长 -> 达成档位 -> 领取奖励 -> 下一轮`

### 可复用规则

- 装置成长要有肉眼可见的阶段变化。
- 投入值、当前收益、下一档奖励必须同屏。
- 如果是循环玩法，结束后要立刻给下一轮动机。

### 风险点

- 成长变化不明显，导致操作没有成就感。
- 数值太多但缺少主线目标。

## 案例 4：节日大富翁 + 小队合作

### 功能定位

- 节日棋盘玩法
- 个人推进与小队协作叠加
- 任务、进度、协作奖励并行

### 页面骨架

- 左侧：活动目录
- 中央：地图/棋盘/路线主区域
- 右侧：小队面板、成员状态、任务入口
- 底部：投骰、行动、阶段奖励

### 核心流程

`进入活动 -> 创建/加入小队 -> 执行行动 -> 阶段推进 -> 个人奖励/小队奖励结算`

### 可复用规则

- 个人行为和团队目标要分开呈现。
- 队员状态必须可见，如在线、可协助、已完成。
- 任务应支持一键跳转，不让玩家自己找。

### 风险点

- 小队信息与主棋盘争抢注意力。
- 玩家不知道当前行为是在帮自己还是帮团队。

## 案例 5：围剿变异猴 - 等级拓展

### 功能定位

- 多人战斗准备
- Buff 选择
- 编队与历史战绩联动

### 页面骨架

- 主页：队伍概览、挑战入口
- 子弹窗：Buff 选择、编队调整
- 附属页：战绩、历史记录、推荐配置

### 核心流程

`打开玩法 -> 查看队伍 -> 配置 Buff -> 调整编队 -> 确认挑战 -> 查看历史结果`

### 可复用规则

- Buff 弹窗同时提供效果说明和来源说明。
- 编队位变化要实时刷新关键战斗指标。
- 历史战绩页应该支持复盘，不只是榜单展示。

### 风险点

- Buff 太多，缺少分类与预览。
- 编队调整后没有即时反馈。

## 案例 6：新 Gacha + 累计活动

### 功能定位

- 抽奖主玩法
- 任务累计副玩法
- 不同模式切换

### 页面骨架

- 左侧：模式切换
- 中央：Gacha 棋盘/转盘/推进区
- 右侧：奖励预览、次数、规则、任务
- 弹窗：抽取结果、大奖揭示、任务奖励

### 核心流程

`进入活动 -> 选择玩法模式 -> 发起抽取 -> 动画推进 -> 结果揭晓 -> 累计奖励回收`

### 可复用规则

- 抽取前、抽取中、抽取后的节奏要清楚。
- 主抽奖区必须是视觉中心。
- 累计活动作为陪跑系统，不能压过主玩法。

### 风险点

- 模式太多导致切换理解成本高。
- 玩家看不懂抽奖机制，只能盲点。

## 案例 7：节日版赛车维修组队系列活动

### 功能定位

- 维修/建设主题活动
- 多步骤阶段任务
- 个人贡献 + 组队推进

### 页面骨架

- 活动主页：赛车主体、维修阶段、进度线
- 队伍面板：成员、邀请、贡献
- 子页：奖励兑换、商店、任务清单

### 核心流程

`进入活动 -> 参与队伍 -> 执行维修相关行为 -> 阶段推进 -> 解锁新外观/奖励 -> 兑换`

### 可复用规则

- 阶段感必须通过主物体变化体现。
- 队伍列表与邀请入口要短路径直达。
- 维修完成后应有明显阶段升级反馈。

### 风险点

- 页面模块多，容易拥挤。
- 阶段奖励、兑换、任务三套系统互相打架。

## 案例 8：新节日累充活动 - Bingo 返利

### 功能定位

- 累充返利
- 棋盘点亮
- 连线触发大奖

### 页面骨架

- 左侧：页签
- 中央：Bingo 棋盘
- 右侧：任务、次数、返利档位
- 弹窗：连线奖励、大奖结果、购买补次

### 核心流程

`完成累充 -> 获得次数 -> 点亮格子 -> 触发连线 -> 领取返利 -> 冲击大奖`

### 可复用规则

- 棋盘状态至少区分未点亮、已点亮、大奖、已领取。
- 连线成功要有线条、闪光、中心聚焦等强反馈。
- 棋盘外信息必须服务于“再来一次”的决策。

### 风险点

- 连线结果不明显，玩家不知道是否触发。
- 次数获取与消耗规则说不清。

## 案例 9：节日集卡册 + 相关礼包

### 功能定位

- 卡册收集
- 收集奖励
- 礼包售卖与活动联动

### 页面骨架

- 入口露出：头像、个人页、banner
- 主页：卡册总览、收集进度、奖励
- 子页：单卡详情、礼包、任务
- 弹窗：开卡结果、合成结果、奖励领取

### 核心流程

`进入活动 -> 查看卡册 -> 获取卡片 -> 激活收集进度 -> 领取阶段奖励 -> 承接礼包购买`

### 可复用规则

- 卡片品质和收集状态要统一表达。
- 收集奖励应按总进度给反馈，而不是只看单卡。
- 礼包入口顺着缺卡、差一点、快完成等动机出现。

### 风险点

- 卡册、商店、任务入口过散。
- 玩家只看到卖礼包，看不到收集乐趣。

## 案例 10：挖矿砍价礼包

### 功能定位

- 行为积累换低价
- 挖矿/资源转化
- 分阶段报价礼包

### 页面骨架

- 主页：矿机/矿石主体、当前价格、剩余降价空间
- 子区：进度、阶段收益、历史降价
- 弹窗：确认购买、继续降价、阶段结果

### 核心流程

`进入活动 -> 执行挖矿/砍价行为 -> 价格下降 -> 评估购买 -> 确认支付 -> 奖励领取`

### 可复用规则

- 当前价、原价、最低价、达到条件要同屏。
- 降价必须与视觉变化绑定，如矿石升级、机器变化、数字跳变。
- 不购买玩家也要知道下次还能怎么继续降。

### 风险点

- 价格变化逻辑不透明。
- 付费点来得太早，打断体验。

## 横向提炼：P2 常见页面母版

### 母版 A：左导航 + 中玩法 + 右任务/奖励

适用：

- 大多数节日活动
- Bingo
- Gacha
- 集卡

### 母版 B：中心装置 + 四周信息

适用：

- 金蛋
- 猴猴币
- 砍价礼包

### 母版 C：主物体进度 + 团队面板

适用：

- 小队合作
- 赛车维修
- 联盟共建

### 母版 D：战前准备 + 配置弹窗

适用：

- Buff 玩法
- 多人编队
- 英雄共享养成

## 横向提炼：P2 共性体验法则

- 主玩法区永远先于规则说明吸引注意。
- 所有运营活动都要明确“当前能做什么”和“做完得到什么”。
- 商业化入口要顺着玩法动机出现，不要突然插脸。
- 协作活动必须明确个人收益与团队收益。
- 奖励反馈必须分层：普通奖励快给，大奖励强演出。
